# Phase 9: explicit official doc-string execution content

Contract: `DocStringSemantics::Gherkin43` is an opt-in content policy on
`GherkinEnv::with_docstring_semantics`. It is independent of dialect selection.
`Default`, `new`, and `new_latest` retain Legacy content unless explicitly changed.
The public Step shape remains unchanged: optional media type is removed from the
payload but is not exposed as a new native field in this phase.

## Source and accepted behavior

Pinned source: cucumber/gherkin v43.0.0,
commit `3d70e2bb4e0f16a568ee539a5ce0b03fb247a777`.
Unmodified official fixture/AST files and MIT license are in
`tests/fixtures/gherkin43-docstrings`, with source hashes in PROVENANCE.md.
The full official docstrings fixture covers XML media type, relative indentation,
under-indented content, interior blank lines, triple-quote/backtick delimiters,
embedded alternative delimiters and escaped active delimiters. The official
combined-arguments fixture covers both table/doc-string orders.

The native official-content rule is separate and line-oriented. It excludes
opening header and closing separator lines, removes at most the opening delimiter
indentation from each content line, normalizes line endings, preserves remaining
content whitespace, and joins body lines without synthetic edge newlines.
Only a matching delimiter at the beginning of an indented line closes the block.
Closing-line suffix text is ignored, following the official token matcher rather
than imposing an invented extra restriction. Missing/mismatched closures and a
same-line-only opening/closing pair are rejected in this mode; no legacy fallback
is permitted. Legacy matching/dedent rule remains unchanged behind its mode guard.

Tagged primary implementation reference:
https://github.com/cucumber/gherkin/blob/v43.0.0/javascript/src/GherkinClassicTokenMatcher.ts
and GherkinLine.ts. Matching escaped delimiters use the tagged JavaScript token
matcher's first replacement per content line. This phase does not claim a complete
cross-implementation resolution for multiple escaped separators on one line,
Unicode whitespace indentation, or every malformed grammar form.

## Acceptance and boundary

Ten scenarios were authored before production edits: three external-oracle
fixture cases, four exact legacy-policy preservation cases, and three malformed
closure cases. The upstream `.crlf` Git blob contains LF bytes; its Given step
converts only line endings to actual CRLF and compares to its unmodified official
expected content. No oracle is generated by local production code or Node.
Existing argument, escaping and dialect-policy scenarios remain unchanged.

Source changes: parser.rs adds enum/environment selection and separate official
rule; lib.rs re-exports DocStringSemantics. Both production files were synced into
Cucumber's vendor snapshot with updated hashes/provenance. Parent owns the
Cucumber-level option and later outline execution integration.

Phase-end command: `cargo test --test step_arguments`, exit 0 on 2026-11-17.
Observed **1 feature, 60 scenarios passed, 202 steps passed** with no skipped
acceptance steps or compiler warnings. This includes the 50 prior scenarios and
10 new doc-string policy scenarios. External-oracle comparisons assert 18 exact
contents: eight LF, eight actual CRLF, and two combined-argument payloads.

Evidence: `../cucumber/docs/compatibility/evidence/phase9-docstrings-parser-bdd.log`.
The first phase-end run passed; no implementation or assertion corrections were
needed. No unit suite, generic cargo test, lint/check, or premature build ran.
Cucumber handler execution/outline substitution is parent-owned follow-up
integration and is not claimed by these parser-only observations.


## Phase 13 root differential acceptance

Official-mode doc-string indentation now uses the exact ECMAScript whitespace
set, including NBSP/BOM and Unicode space separators, with character-counted
opening indentation. Legacy grammar stays unchanged. This parser source is
byte-synchronized with cucumber/vendor/gherkin; table-policy changes from the
independent Phase 15 are retained.

The root Cucumber target `messages_docstrings` executes actual native step
handlers and compares complete source AST/Pickles to the isolated exact
@cucumber/gherkin43.0.0 oracle. At phase end it passed 15 scenarios/86 steps,
including delimiter suffixes, active/inactive repeated escapes, full whitespace
and NEL/zero-width boundaries, LF/CRLF, and legacy preservation. Prior root
source graph19/80 and handler/snapshot3/13 BDD also passed. Evidence and exact
contract: ../cucumber/docs/compatibility/messages-docstrings.md. No code pushed.
